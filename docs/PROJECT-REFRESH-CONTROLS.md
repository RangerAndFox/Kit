# Project refresh controls

## Team workflow

Save edits in the Production Control Center Sheet. In an operational project's
Slack Overview, follow **Refresh this project** beside **Last synced**, then
press **Sync now** on Kit's project control message. It is pinned when the
installation grants pin permissions; the Overview permalink works without pins.
Producers/admins can also use `/kit refresh 2645`, or tell Kit
“sync this project” in the project channel. Artist access is not expanded.

The immediate response means **queued**, not complete. Kit sends each requester
one private completion/failure receipt. Repeated clicks coalesce while a request
is pending. Overview is published last, after Reference/Schedule; a failed
Schedule update cannot stamp a new successful Overview time. Notes & Feedback
remain human-owned and are never replaced by this sync.

The Sheet's Last Share label/URL accept Figma or other HTTPS review links, not
only Frame.io. URL-only edits now produce a visible link. Bare Sheet IDs (2645)
resolve uniquely against the configured workbook's canonical project codes
(2645-Microsoft), avoiding an unnecessary workbook-wide fallback. Ambiguous IDs
still fail safe. Share discovery/tracking belongs to the coordinator; this
change adds no link-watching agent or independent Last Share writer.

## Durable implementation

Railway verifies the Socket Mode actor, resolves their current producer/admin
role and workspace, and validates the connected project. Button requests must
originate in the control's bound channel. A service-only RPC atomically queues
the existing `reconcile_project` control-outbox action and deferred private
receipts; it serializes enqueue by project binding. An optional Inngest event
wakes the existing drain, with its minute cron as recovery. There is no second
sync owner: the canonical workbook lease, source hashes and row metadata remain
authoritative. Targeted manual refreshes do not advance the workbook cursor.

Apply the additive project-refresh migration before releasing either runtime.
Both service-only RPCs are exercised by the PGlite database test, including
cross-workspace refusal, role grants, stale leases and atomic receipt release.
The `finish_slack_project_refresh` wrapper releases receipts only when the
parent outbox action reaches sent/review. No public function grants are added.

## Project dropdowns

The live workbook's eight project filter cells use `Lists!Y5:Y`, maintained by
a native formula generated by `projectFilterFormula()`. It shows unique
Active/On Hold/Needs Review project numbers in numeric-then-suffix order,
excluding test IDs 9998/9876. Whole-column source ranges include newly appended
projects. `Lists!Z5:Z` retains the sorted historical ID reference. Validation is
non-strict so users may type a historical ID. Existing selections and source
rows, metadata, formulas, formatting and lifecycle filters are preserved.

Filter cells: Control Center B3, Projects C3, Project Specs C3,
Daily Assignments B3, Links B3, Workback C3, Deliverables B3, Status Log B3.
Helpers occupy the previously empty Lists Y4:Z1000. Do not sort physical source
rows to sort these menus, or rewrite their developer metadata.

## Verification / rollback

Run app tests, Bolt tests, typecheck, lint ratchet, migration checks and build.
After release verify both deployed SHAs, Inngest registration, a real Overview
link and the private completion receipt. A test-only pass is not live proof.
Rollback the application commit if needed; leave the additive columns/RPCs and
outbox history intact. Dropdown rollback changes only their validation source;
never delete historical project rows as part of a menu rollback.
